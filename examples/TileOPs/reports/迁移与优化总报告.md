# TileOPs GPU→NPU 迁移与优化总报告（CANN 9.0.0）

> 范围：任务书 §5 的 **19 个独立 Op 接口**。

> torch 2.7.1+cpu / torch_npu 2.7.1.post4。

> [`FINAL_DELIVERY_20261018.md`](FINAL_DELIVERY_20261018.md) §2（机器可读 `perf_data/canonical.json`）。
> 性能口径：`msprof op` Task Duration + Roofline SOL 利用率（访存 ≥70% / 算力 ≥60%）。

## 结论

1. **19/19 接口可用**：GDN 的 in-scope 主路径（K1 cumsum + K2 split blocksolve + K6 batched）已交付，
   `test_gdn.py` 10/10；小 shape 与 K5/CP 走 fallback。
2. **全 shape 严格达标只有 1 个**：Sub（15/15）。Add 10/11（最低 69.37% 贴线）、Lerp 9/11、
   Hardswish 2/6、ClampScalar 1/11；shape 级 **40/136（29.4%）**。
3. **两个最大杠杆已落地**：Conv1d 通用 kernel **wav2vec2 17.7×**、Conv3d unet **21.3×**；
   GLA persistent、GeluAndMul dtype 分化（−43.6%）、BatchNormBwd subid 分片（−33~46%）同期落地。
4. **未达标不等于没收益**：12 个算子拿到真实时延收益但 ratio 未过线（判据失配 / 带宽地板 / 编译器缺陷）；
   只有 Isnan 判为无收益、不采纳。
5. **未收口项都有证据**：GDN K5/CP 与性能数据、Conv1d bias（CG-2026-0028/0029）、Add 贴线。
   没有新工具链或新证据前不建议继续投入。
