### Transferable Lessons（可迁移教训）

- Before running `integrate_kernel.py`, diff the meta `extracted_functions` against the real `examples/{op_slug}/{func}/` product dirs. If the meta is a superset, pass `--functions <real products>` AND reconcile the wrapper: the Stage 0 wrapper keeps importing the full extracted set, so the auto block would import phantom names. Pre-narrow the wrapper's `.{extracted_module}` import to the integrated functions only (glue layer), run the script, then re-add the out-of-unit helper imports from the Stage 0 module.
- If a Stage 0 wrapper still imports out-of-unit helpers from `.{extracted_module}` after integration, a re-run of `integrate_kernel.py` MUST pass `--extracted-module {op_slug}_kernel` (else `parse_wrapper_imports(wrapper, extracted_module)` returns the helper names and the smoke checks them against the package, failing). The wrapper gets its idempotency guard (`from .{op_slug}_kernel import`) so it is not rewritten again.
- Keep out-of-unit GPU reference helpers on the Stage 0 `.{extracted_module}` file; do NOT copy them into `{op_slug}_kernel/` just to satisfy the wrapper import — the NPU integration package should contain only the migrated kernel(s), and gate 5 S5-FUNCS tracks the migration-unit function set, not the Stage 0 extracted set.
- When a report is `partial` because msprof fell back to events, first check whether the projected kernel is capturable at all: a sibling op (CumprodFwdOp here) on the same device/toolchain produced `captured_op_count=1` with kernel `main`, so the fallback is op/launch-path specific, not a blanket profiler outage. Record only; never "fix" performance/tooling in Stage 5.
