### Transferable Lessons（可迁移教训）

- Run `integrate_kernel.py` **exactly once** per wrapper state and always with `source /workspace/env.sh` first. If a re-run is unavoidable after the wrapper is already rewritten, manually restore the aggregation `__init__.py` re-exports (`{func}` plus any helper names the wrapper imports, e.g. `adaptive_bin` / `max_adaptive_bin_extent`), because the script cannot recover the wrapper import-name list from an already-rewritten wrapper.
- The integration `--meta` path is resolved relative to the current directory: from `examples/TileOPs` use `tileops/kernels/pool/adaptive_max_pool2d/.migration_meta.json` (the repo-root-relative `examples/TileOPs/...` form raises `FileNotFoundError`).
- For a shared family test file (`tests/ops/<slug>.py`, e.g. pool holding both avg and max), the report CLI `--op X` runs the **whole file**: the sibling operator's correctness/benchmark cases also execute and count. Judge the op under test from the per-operator rollup in `run.json` (`operators` / `performance.cases[].operator`), not from `summary.correctness_tests`.
- Verdict comes from `run.json` (`summary.correctness_passed`, `status`), never from the CLI exit code: `partial` yields a nonzero exit while correctness still passes. Run the report **last** — it must post-date every edit to the wrapper / package `__init__.py` / integrated kernel `.py` or the mtime-based `S5-REPORT-STALE` gate fails.
- Stage 5 `S5-ASCEND-MODE` requires the `ascend_mode` literal on the class whose **direct** base is `Kernel`. For the two-layer pool wrapper (`AdaptivePool2dKernelBase(Kernel)` + concrete subclass) keep the literal on the base, equal to the integrated kernel module's `ASCEND_MODE` read from the module (here `Developer`) — never guessed from the op name or DESIGN.
