# GDN blocksolve 判定性探针（2026-10-18）

> 目标：判断 `prefill_blocksolve_A_bthd` 的 CG-2026-0003 阻塞能否用「拆 kernel / 改分组 / 改核数」绕开。
> 工具链：CANN 9.0.0 / tilelang 0.1.2 dev root / Ascend910B3。所有命令经 `.agents/tools/npu_lock.sh`。

## 1. 变体

| 变体 | 构造 | 用途 |
|---|---|---|
| `level3_variant.py` | 保留 lev 0–2（3 级 log-doubling），删 lev 3–5，末尾补 `T.copy(l0t, y_blk)` + `F_A` set | 模拟「2 个 kernel 各 3 级」 |
| `level1_variant.py` | 只保留 lev 0，末尾补写 | 判定「链长是否为唯一变量」 |
| `cores1_variant.py` | wrapper 增加 `num_cores`，传 `num_cores=1` | 判定「核数/task 映射是否为触发点」 |
| `run_group.py` | 原版 6 级，`head=2, key_head=2`（`group=1`） | 判定「group 分组是否为触发点」 |

原始 kernel 与 golden 未改；变体只删除/截断 level 块，不修改数学语义（3 级/1 级为**不完整逆**，仅用于编译判定，不参与精度结论）。

## 2. 结果

| 变体 | `S=64,H=2,dk=64` | `S=1024,H=4,dk=128` |
|---|---|---|
| 原版 6 级（对照，历史） | SIGSEGV（`code -11`） | SIGSEGV |
| 3 级 | **SIGSEGV** | **编译并运行成功** |
| 1 级 | **SIGSEGV** | 未测（会话终止） |
| `group=1`（kh=2） | **SIGSEGV** | — |
| `cores=1` | **挂死**（15min 超时，rc=124） | — |

## 3. 结论

1. **大 shape 的 IR 规模问题可以靠拆分解决**：`S=1024,H=4,dk=128` 在 3 级变体下编译并运行成功（原版 6 级必崩）。
2. **小 shape `S=64,H=2` 是独立触发点**：把链降到 1 级仍 SIGSEGV；`group=1`、`cores=1` 均无效（后者转为挂死）。因此「拆 kernel」不是小 shape 的解。
3. 触发点与**链长、group、核数**均无关；剩余嫌疑集中在 `H=2` 的 Vector prelude / strided region / `vbrc+vsub` 形态。
4. **判定**：GDN 仍阻塞。要收口 19/19，需要设计级替代（纯 Vector 前处理、换 tile/布局、或等 CG-2026-0003 修复），不是 1–2h 的 kernel 拆分能解决。

## 4. 复现

```bash
cd examples/gdn_prefill/probe/experiments/18_level_split
# 3 级：两个形状
.agents/tools/npu_lock.sh --wait 0 --wait-idle 180 --timeout 900 -- python3 run_level3.py
# 1 级：小 shape（预期 SIGSEGV）
.agents/tools/npu_lock.sh --wait 0 --wait-idle 180 --timeout 900 -- python3 run_level1.py
# group=1：小 shape（预期 SIGSEGV）
.agents/tools/npu_lock.sh --wait 0 --wait-idle 180 --timeout 900 -- python3 run_group.py
# cores=1：小 shape（预期挂死/超时）
.agents/tools/npu_lock.sh --wait 0 --wait-idle 180 --timeout 900 -- python3 run_cores1.py
```

日志：`/tmp/opencode/gdn_level3_probe.log`、`gdn_level1_probe.log`、`gdn_group_probe.log`、`gdn_cores1_probe.log`（本会话临时目录）。

## 5. 对 gap 记录的增量

- CG-2026-0003 的触发面补充：**同一 kernel 的 `S=64,H=2,dk=64` 在 1 级/3 级/6 级、group=1/2、cores=1/默认下均失败**；`S=1024,H=4,dk=128` 在 3 级下成功。
- 结论：**IR 规模不是唯一变量**；小 shape 存在独立的 codegen 触发形态，拆分策略只对大 shape 有效。
