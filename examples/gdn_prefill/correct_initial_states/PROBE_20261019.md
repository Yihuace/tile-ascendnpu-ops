# GDN K4 / K2 编译探针（2026-10-19，CANN 9.0）

## 结论（先看这里）

**当前 CANN 9.0.0 + `AscendNPU-IR-v11/build-v11`（1.1.0 / 428ab8fd）+ `hivmc 0.2.0` 无法编译任何新 kernel。**

- 最小 `64×64×64` Cube GEMM：`Failed to compile BiShengLIR to binary`
- K4 形状的 Cube 探针：同错
- 纯 Vector K1 `gdn_chunk_cumsum_kernel`（空 cache）：同错
- `test_conv3d_bias[video-down-bias]`（空 cache）：同错
- 之前 23/50/67 passed 都是 **默认 kernel cache 命中**，不是 9.0 现场编译成功

根因仍是 `hivmc 0.2.0` 缺少 LIR 编译能力；这不是 K4 的 kernel 结构问题，也不是加 `--disable-hivm-tensor-compile` 或 Expert/Developer 模式能修的。

## 探针与命令

### 1. 最小 Cube GEMM

`probe_cube_min.py`：`A[64,64] @ B[64,64] -> C[64,64]`，L1 + L0C + `T.gemm` + `PIPE_FIX`。

```bash
source /home/developer/tilelang-mlir-ascend/env_cann90.sh
TILELANG_ASCEND_MODE=Developer python3 probe_cube_min.py
TILELANG_ASCEND_MODE=Expert    python3 probe_cube_min.py
```

结果（两种模式一致）：

```
Failed to compile BiShengLIR to binary
Failed to compile BiShengLIR for device
Failed to compile HIVM IR
```

### 2. K4 形状探针

`probe_compile.py`：K4 的 `m @ h_prev` 修正形式，L1/L0C，`state_v_first=False`。

结果同上：HIR pipeline 通过，`hivmc` 在 LIR→binary 失败。

### 3. 纯 Vector K1（空 cache）

```bash
export TILELANG_CACHE_DIR=/tmp/opencode/tl_cache_vec
python3 tileops/kernels/linear_attention/gdn_prefill/gdn_prefill.py --level L0
```

结果：同一个 `Failed to compile BiShengLIR to binary`。说明不是 Cube 专属问题，而是整个 9.0 JIT 无法产出新 `.o`。

### 4. conv3d 空 cache

```bash
export TILELANG_CACHE_DIR=/tmp/opencode/tl_cache_empty
python3 -m pytest tests/ops/test_conv3d_bias.py -q -k "video-down-bias"
```

结果：`1 failed`，同一个 hivmc 错误。默认 cache 下该用例通过，证明此前结果是缓存命中。

## 对 K2 三段拆分设计的影响

三段拆分的结构本身是可行的：

1. `gram`：Cube，算 `G = k kᵀ`
2. `build_N`：Vector，算 `N = -β·exp(gc_i-gc_j)·G·mask`，并负责 padding 行归零
3. `level_0_1`、`level_2_3`、`level_4_5`：Cube-only，每段 2 级 log-doubling，中间 `T/P` 走 GM
4. `emit_A`：Vector，输出 `A`

它能降低单 kernel 的 IR 规模，规避 CG-2026-0003 的规模触发；但**当前 9.0 连最小 GEMM 都编译不了**，因此该设计现在无法进入 Stage 3。继续写 kernel 没有意义，先解决 hivmc。

## 需要决策

1. **等 CANN 侧提供支持 LIR 的 9.0 hivmc**（唯一不违背“只用 9.0”的完整迁移路径）；
2. **重新启用 9.2**（已知可编译，但与用户当前约束冲突，需明确批准）；
3. **停止 GDN 新 kernel 开发**，保留 correctness-first fallback；
4. 继续用默认 cache 交付（只能跑旧二进制，不能改 kernel，不能算迁移）。

在 1/2 任一条件满足前，K4–K6 和 K2 的开发都无法继续。
